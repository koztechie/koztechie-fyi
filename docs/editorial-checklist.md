# Редакційний чеклист

Застосовуй до кожного нового або суттєво оновленого публічного тексту. Для
технічних процедур замість цього використовуй `docs/testing.md`.

## До написання

- [ ] Визнач тип матеріалу за `docs/content-model.md`: запис, кейс, кладовище,
      вірш, сторінка або розділ.
- [ ] Перевір, що текст має одну зрозумілу мету й не дублює інший URL.
- [ ] Для особистого тексту звірся з приватним `red-lines.md` поза репозиторієм.
      Якщо межа неясна — зупини публікацію та запитай автора.
- [ ] Для матеріалу про третю особу отримай її письмову згоду. Для кейсу також
      потрібна згода роботодавця/клієнта або безпечна абстракція, визначена
      автором; зміна імені сама по собі не знеособлює історію.
- [ ] Не додавай заборонені приватні деталі: дітей, діагнози, сімейні події,
      стосунки, борги, точні адреси чи впізнавані дані третіх осіб.
- [ ] Перевір фактичні твердження, дати, джерела й часовий контекст. Не
      перетворюй припущення або план на підтверджений факт.

## Текст і структура

- [ ] Заголовок конкретний, без клікбейту, фальшивої інтриги й штучних цифр.
- [ ] Текст написаний власним голосом; немає забороненої лексики й
      неперевірених суперлативів.
- [ ] Є семантична ієрархія заголовків і один змістовий `h1` у результаті.
- [ ] Посилання мають зрозумілий текст; зображення — точний alt або
      декоративну семантику.
- [ ] Для чутливої теми задано дозволений `content_warning`; попередження
      відповідає фактичному змісту.
- [ ] Для перекладу перевірено змістову відповідність, однаковий slug/entry та
      коректний `translation_status`.
- [ ] Метадані відповідають `docs/content-model.md`; окремо перевір title,
      description і OG-поля у зібраному HTML.

## Перед публікацією

- [ ] Створи файл із `content/_template-post.md`; видали всі плейсхолдери,
      включно з `permalink: false`.
- [ ] Залиш `draft: true`, доки редакційна й технічна перевірки не завершені.
- [ ] Прогони `npm run validate`, `npm run voice-lint`, `npm run build` і
      `npm run qa:all`.
- [ ] Переглянь обидві мовні версії та відповідні зібрані сторінки.
- [ ] Перевір `git diff`: не додано `dist/`, приватних файлів, секретів чи
      стороннього матеріалу без дозволу.
- [ ] Після проходження гейтів зніми `draft: true` і публікуй за
      `docs/deploy.md`; не деплой вручну в обхід авторизованого процесу.
