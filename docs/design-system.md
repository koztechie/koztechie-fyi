## 1. ЕСТЕТИКА: This Protocol Has Been Printed Out. It Is Warm and Accurate.

**Статус: ЗАТВЕРДЖЕНО** (крок 77, 2026-10-18; перейменовано 2026-10-26 за рішенням автора).

### 1.1. Визначення

Візуальна мова, що поєднує три риси:

| Риса | Значення |
|------|----------|
| **Тепла** | Тепла тонована бумага, високий контраст, багато повітря. Сайт як роздрукований протокол, а не вітрина |
| **Глітч** | Точкові збої: один момент несподіванки на сторінці. Не хаос, а акцент |
| **Мінімалізм** | Нічого зайвого. Кожен елемент має функцію або причину |

### 1.2. Принципи

| # | Принцип | Наслідок |
|---|---------|----------|
| 1 | **Візуальна тиша** | Whitespace ≥ 20% — повноправний елемент, не «порожнеча, яку треба заповнити» |
| 2 | **Чесна типографіка** | Текст має читатися як архівний документ, а не як реклама |
| 3 | **Глітч — рідкість** | Не більше 3 сигнатур на сторінку. Їх вичерпний перелік — §7 |
| 4 | **Тема — ОС, не сайт** | `prefers-color-scheme`. Без перемикача, без збереження вибору |
| 5 | **Максимум 6 кольорів** | На тему. Без винятків, окрім ізольованої палітри NICHLYST |

### 1.3. Чому саме так

| Аргумент | Пояснення |
|----------|-----------|
| Архів, не вітрина | Сайт фіксує свідчення. Дизайн не повинен продавати те, що лише фіксує |
| Повільна машина | A4-4020, 50 КБ сторінки. Складна графіка тут неможлива і не потрібна |
| Виживання | Мінімалізм старіє повільніше за тренди. Глітч — єдиний елемент, що має право бути «за часом» |
| Доступність | Високий контраст і чиста типографіка — це одразу AAA, а не після ретуші |

### 1.4. Межі

Естетика НЕ поширюється на `/nichlyst/`: гра має ізольовану палітру (5 кольорів,
`TECH_STANDARDS.md` §4). Решта сайту — виключно цей розділ.

Естетика НЕ є декоративним завданням. Якщо елемент не працює без оздоблення —
він видаляється, а не прикрашається.

## 2. ЗАБОРОНИ (PROHIBITIONS)

**Статус: ЗАТВЕРДЖЕНО** (крок 78, 2026-10-18).

**Канонічний перелік.** Автоматична перевірка: `check.mjs`, розділ 2.
Жодних винятків, окрім явно зазначених.

### 2.1. Градієнти

| Заборонено | Заміна |
|------------|--------|
| `linear-gradient` | Суцільний колір з палітри (§4) |
| `radial-gradient` | Суцільний колір |
| `conic-gradient` | Суцільний колір |
| Градієнтні банери, «забарвлені» секції | Фон «ПАПІР» або «БУНКЕР» |

**Причина:** Градієнт — маркер типового ШІ-портфоліо (`DECISIONS.md` §6.1).
Додає ваги, не додаючи сенсу.

### 2.2. Тіні

| Заборонено | Заміна |
|------------|--------|
| `box-shadow` | Межа `border: 1px solid var(--rule)` |
| `text-shadow` | Немає. Контраст тексту і так AAA |
| `drop-shadow` (filter) | Немає |
| Тіні «для об'єму» | Чіткі межі |

**Виняток один:** фокус. `outline: 2px solid var(--accent)` — це не тінь.

**Причина:** Тінь вимагає розрахунку на повільному CPU. Мінімалізм обходиться
межею.

### 2.3. Заокруглення

| Заборонено | Заміна |
|------------|--------|
| `border-radius` > 4px | Максимум 4px, або 0 |

**Чому 4px:** Межа, за якою форма починає читатися як «м'який блок». До 4px —
геометрія, після — іграшка. Правило зафіксовано: `DECISIONS.md` §6.3.

### 2.4. Гласморфізм

| Заборонено | Заміна |
|------------|--------|
| `backdrop-filter: blur()` | Суцільний фон `var(--bg)` або `var(--surface)` |
| Напівпрозорі шари поверх контенту | Шари без контенту під ними |
| «Скляні» картки | Текстові блоки з межею |

**Причина:** `backdrop-filter` — найважча із заборонених властивостей.
На A4-4020 вона рве прокрутку.

### 2.5. 3D

| Заборонено | Заміна |
|------------|--------|
| `perspective` | Немає. Сторінка — площина |
| `transform-style: preserve-3d` | `flat` (за замовчуванням) |
| `rotate3d`, `translate3d`, `scale3d` | 2D-аналоги: `rotate`, `translate`, `scale` |
| 3D-куби, «центрифуги», паралакс-сцени | Немає |

**Виняток:** мікрогліч (§7) анімує `transform`/`opacity` у 2D. Це не 3D.

**Причина:** 3D-трансформації потребують GPU-прискорення, якого на цій
машині немає (Radeon HD, драйвери 2014 року).

### 2.6. Додатково заборонені властивості

| Властивість | Причина |
|-------------|---------|
| `style=` атрибути в HTML | Стиль належить стилям, не розмітці |
| Анімовані фони | `AGENTS.md` §4 |
| `!important` без запису в документ | Стилі, що потребують `!important`, — погані стилі |

### 2.7. Верифікація

| Перевірка | Де |
|-----------|-----|
| Автоматична | `check.mjs` розділ 2: градієнти, тіні, radius > 4px, backdrop-filter |
| Ручна | Рев'ю перед публікацією: 3D, `style=`, анімовані фони, `!important` |

### 4.3. Контраст (CONTRAST)

**Статус: ЗАТВЕРДЖЕНО** (крок 83, 2026-10-18).

**Правило:** Основний текст — мінімум 7:1. Це WCAG 2.1 рівень AAA (1.4.6).
Не AA (4,5:1). AAA.

### 4.3.1. Що перевіряється

| Категорія | Пар | Норма |
|-----------|-----|-------|
| Текст | `ink` на `bg`, `ink` на `surface` | ≥ 7:1 |
| Другорядний текст | `ink-dim` на `bg`, `ink-dim` на `surface` | ≥ 7:1 |
| Лінки та акценти | `accent` на `bg`, `accent` на `surface` | ≥ 7:1 |
| Лінійки та межі | `rule` на `bg`, `rule` на `surface` | ≥ 3:1 |
| Фокус | `accent` на `bg`, `accent` на `surface` | ≥ 3:1 |

**8 різних пар на палітру. 16 разом.** Скрипт робить 10 перевірок на
палітру (20 разом): `accent` на `bg`/`surface` рахується двічі — як текст
(≥ 7) і як фокус (≥ 3). Сильніша норма (7) визначає значення.

### 4.3.2. Формула

WCAG 2.1, відносна яскравість (relative luminance):

```
L = 0.2126·R + 0.7152·G + 0.0722·B
де R, G, B — лінійні значення каналів (не sRGB)
Контраст = (L_світліший + 0,05) / (L_темніший + 0,05)
```

Конвертація sRGB → лінійна: `c ≤ 0,03928 → c/12,92`, інакше `((c+0,055)/1,055)^2,4`.

**Реалізація:** `scripts/palette-check.mjs`. Ручний розрахунок не потрібен
і не є доказом — доказом є вивід скрипта.

### 4.3.3. Чому AAA, а не AA

| Аргумент | Пояснення |
|----------|-----------|
| Архів, не кампанія | Текст має читатися роками, на будь-якому екрані, без зусиль |
| Повільна машина | На слабкому LCD різниця між 4,5:1 та 7:1 — різниця між читанням і втомою |
| Без ретуші | AAA з самого початку, а не «підправимо після аудиту» (`§1.4`) |
| Запас | Якщо текст AAA на обох темах — на засніженому екрані він лишиться читабельним |

### 4.3.4. Що НЕ є текстом

| Елемент | Норма | Чому |
|---------|-------|------|
| `rule` (лінійки) | ≥ 3:1 | Це межа, не зміст. Лінійка 7:1 — чорна смуга, а не роздільник |
| Фокус-індикатор | ≥ 3:1 | WCAG 2.4.11 (Focus Appearance). 7:1 тут завищення |
| Декоративні елементи | не перевіряється | `aria-hidden="true"`. Не несуть інформації |
| Емодзіі в тексті | не перевіряється | Кольори емодзі не піддаються зміні |

**Винятків для тексту немає.** Жодного «великий шрифт може бути менш
контрастним». Великий шрифт — теж текст.

**Статус: ВІДМОВЛЕНО** (крок 84, 2026-10-18).

**Рішення:** Семантичні кольори (помилка, підтвердження) НЕ вводяться.

### Чому відмова

### 4.4. Ліміт кольорів (COLOR BUDGET)

**Статус: ЗАТВЕРДЖЕНО** (крок 86, 2026-10-18).

окрім ізольованої палітри NICHLYST (`AGENTS.md` §4).

### 4.4.1. Що рахується

| Рахується | Не рахується |
|-----------|--------------|
| Кожен hex у таблиці палітри | `transparent`, `inherit`, `currentcolor` |
| Змінна з власним значенням | Значення наявної змінної (`var(--ink)`) |
| Напівпрозорість як окремий колір: `#0a526633` | Той самий hex без альфа-каналу |
| Колір у будь-якому файлі `src/styles/` | Hex у `docs/` (документація, не сайт) |

**Прозорість — це колір.** `--accent-veil: #0a52661a` — сьомий колір, хоча
він «той самий accent». Напівпрозорий шар має власну візуальну вагу.

### 4.4.2. Чому 6

| Аргумент | Пояснення |
|----------|-----------|
| Шість ролей, не шість «гарних» | `bg`, `surface`, `ink`, `ink-dim`, `accent`, `rule` — кожен має функцію. Сьомий не має |
| Пам'ять читача | 6 кольорів можна тримати в голові. 12 — ні. Архів має бути впізнаваним з першого відвідування |
| Палітра = документ | Якщо колір не вміщується в таблицю — він не частина системи, а імпровізація |
| Сімейна звичка | Розробник, що звик до 12 кольорів, бачить 6 як «сіро». Це не сіро. Це тихо (§1.2) |

### 4.4.3. Виняток: NICHLYST

`/nichlyst/` має ізольовану палітру з 5 кольорів (`TECH_STANDARDS.md` §4,
`DECISIONS.md` §3). Вона не додається до основних 6, бо:

1. Не змішується з ними. Жодна змінна гри не виходить за межі `nichlyst.njk`.
2. Контраст ≥ 7:1 перевіряється окремо (§36.5 DECISIONS).
3. Це інший документ. Ліміт 6 — для архіву, не для гри.

### 4.4.4. Верифікація

```bash
npm run palette
```

Скрипт рахує значення в кожній таблиці §4.1/§4.2 і падає при 7+.
Альфа-hex (`#RRGGBBAA`) ловиться окремою перевіркою: прозорість — колір
(§4.4.1), але в ліміті вона не рахується коректно і ламає розрахунок
контрасту. Тож альфа в палітрі — заборонена взагалі.
Додатково: `check.mjs` розділ 3 ловить hex поза `themes.css`/`nichlyst.css`/
`print.css` — тобто будь-яку спробу заховати колір в інший файл.

**Перевірено:** обидві палітри — рівно 6. Відмова від семантичних
кольорів (§4.3.6) — прямий наслідок цього ліміту.

## 5. ТИПОГРАФІКА (TYPOGRAPHY)

**Статус: ЗАТВЕРДЖЕНО** (кроки 87–92).

Текст — головний носій змісту цього сайту. Типографіка не оздоблює
зміст, вона його видає.

### 5.1. Текст: системний стек із засічками

**Статус: ЗАТВЕРДЖЕНО** (крок 87, 2026-10-18).

```css
--font-text: Georgia, "Times New Roman", "Noto Serif", serif;
```

Реалізація: `src/styles/core.css`.

| Ланка | Покриття | Чому в стеці |
|-------|----------|--------------|
| `Georgia` | Windows, macOS, iOS, Android | Найширше покриття з одним іменем. Кирилиця є |
| `"Times New Roman"` | Старий Windows, Linux з мовою | Резерв, коли Georgia немає |
| `"Noto Serif"` | Linux без Georgia | Вільний шрифт у багатьох дистрибутивах |
| `serif` | Все інше | Остання ланка. ОС обере сама |

### 5.2. Чому засічки

| Аргумент | Пояснення |
|----------|-----------|
| Архівна читабельність | Засічки краще ведуть око вздовж рядка в довгих текстах. Це сайт есеїв, не лендінгів |
| Книжковість | §1: «текст має читатися як архівний документ». Засічки — типографіка документа, не інтерфейсу |
| Відмова від тренду | Гротеск для тексту — ознака портфоліо-шаблону. Ми робимо протилежне |
| Системність | 0 запитів шрифтів. Georgia вантажиться з ОС, не з мережі |

### 5.3. Що НЕ набирається засічками

| Елемент | Стек | Крок |
|---------|------|------|
| Шапка, підвал, мітки | системний гротеск | 88 |
| Код, цифри-акценти | моноширинний (самохостинг) | 89 |
| Заголовки | той самий засічковий, що й текст | 88 |

**Заголовки — не гротеск.** Це свідоме рішення: весь змістовий текст сайту
набрано одним стеком. Розподіл «заголовки гротеском, текст засічками» —
це мовна гра, а не ієрархія. Ієрархія — через розмір (§5.4, крок 90).

### 5.4. Верифікація

| Перевірка | Де |
|-----------|-----|
| Стек у `core.css` | `--font-text` |
| Жодного стороннього шрифтового origin | `check.mjs` розділ 7б |
| `font-display` для woff2 | `check.mjs` розділ 7б |

Поки немає woff2 (крок 89) — акцентні мітки тимчасово падають на системний
моно (`ui-monospace`). Це не порушення, а перехідний стан.

### 5.5. UI: системний гротеск

**Статус: ЗАТВЕРДЖЕНО** (крок 88, 2026-10-18).

```css
--font-ui: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
```

Реалізація: `src/styles/core.css`.

| Ланка | Покриття | Чому в стеці |
|-------|----------|--------------|
| `system-ui` | Сучасні ОС. Найменше явне ім'я | ОС сама обирає свій гротеск. Windows → Segoe, macOS → SF, Android → Roboto |
| `-apple-system` | macOS, iOS до появи `system-ui` | Резерв для старих Safari |
| `"Segoe UI"` | Windows, якщо `system-ui` не спіймано | Явна ланка на випадок збою системного рішення |
| `Roboto` | Android, Linux | Якщо `system-ui` не відпрацював |
| `sans-serif` | Все інше | Остання ланка. ОС обере сама |

### 5.6. Чому гротеск для UI, а не моно

| Аргумент | Пояснення |
|----------|-----------|
| Роль, не смак | Шапка та підвал — службова інфраструктура. Вони не читаються, вони орієнтують |
| Розрізнення | Текст (засічки) — зміст. UI (гротеск) — межа змісту. Різниця стеків читається без підпису |
| Моно — для акценту | Моноширинний зарезервовано для «лінійки запису» (§7, крок 94) та коду. Якщо він буде і в UI — він перестане бути акцентом |

**Моно для UI не використовується.** Моноширинний стек — це сигнатурний
засіб (§7). Розтікати його по шапці — вбити сигнатурність.

### 5.7. Верифікація

| Перевірка | Де |
|-----------|-----|
| Стек у `core.css` | `--font-ui` |
| Спадкування: UI не застосовується до `<article>` | Крок 100+, лейаути |
| `system-ui` перший у стеці | `core.css` |

Спадкування контролюється лейаутами, не змінною. `--font-ui` ніколи не
призначається на `body`: `body` завжди `--font-text`. Це правило, а не
налаштування.

### 5.9. Шкала розмірів

**Статус: ЗАТВЕРДЖЕНО** (крок 90, 2026-10-18).

Ratio 1.25. Шість розмірів. База 1rem = 16px (безпечне значення
браузера за замовчуванням, не перезаписується).

| Змінна | rem | px | Роль |
|--------|-----|----|------|
| `--text-sm` | 0.8 | 12,8 | Мітки, підписи, дати, UI |
| `--text-base` | 1 | 16 | Основний текст |
| `--text-lg` | 1.25 | 20 | Лід, h3 |
| `--text-xl` | 1.5625 | 25 | h2 |
| `--text-xxl` | 1.9531 | 31,3 | h1 |
| `--text-display` | 2.4414 | 39,06 | Теза головної (h1) |

**Перевірено:** кожне співвідношення сусідніх кроків = рівно 1.2500.

### 5.9.1. Чому 1.25

| Аргумент | Пояснення |
|----------|-----------|
| Відчутний крок | 1.25 (мажорна терція) — мінімум, при якому розмір розрізнюється оком. 1.125 — занадто дрібно для 5 рівнів |
| Не кричить | 1.333 (мажорна кварта) дає різкі стрибки між h2 та h1. На 2-ядерній машині з великими текстами це втомлює |
| Архівність | Скромна шкала читається як документ, не як лендінг. Лендінги люблять 1.5+ |

### 5.9.2. Чому 6, не більше

| Аргумент | Пояснення |
|----------|-----------|
| Рівнів документа — 4 | h1, h2, h3, текст. Додаткові — для ліда й тези головної, не для h4 |
| `h4`+ не підтримується | Tufte CSS §Fundamentals: «якщо відчуваєш потребу в h4 — перероб документ» (§3.6) |
| 7-й розмір = невирішена ієрархія | Якщо елемент не вміщується в 6 — він не має бути текстом цього рівня |

### 5.9.3. Ширина та одиниці

| Правило | Чому |
|---------|------|
| Тільки `rem`, не `px` | Користувач може змінити базовий розмір шрифту в ОС. `px` ігнорує це, `rem` — ні |
| База не перезаписується | `html { font-size }` заборонено. 1rem = 16px — константа браузера |
| Ширина рядка — `68ch` | Окремий крок 91. Не плутати з шкалою |

### 5.9.4. Верифікація

| Перевірка | Де |
|-----------|-----|
| 5 змінних у `core.css` | `--text-sm` … `--text-xxl` |
| Співвідношення 1.25 | обчислено, перевірено 4 пари |
| `rem`, не `px` | `TECH_STANDARDS.md` §4 (responsive) |
| Жодного `html { font-size }` | ручна перевірка |

**Не додавай 7-й розмір.** Якщо з'явився новий рівень тексту — спочатку
перепиши документ, потім шкалу.

### 5.10. Ритм і ширина рядка

**Статус: ЗАТВЕРДЖЕНО** (крок 91, 2026-10-18).

| Токен | Значення | Призначення |
|-------|----------|-------------|
| `--leading` | `1.6` | `line-height` основного тексту |
| `--measure` | `68ch` | Максимум символів у рядку |

Реалізація: `src/styles/core.css`.

### 5.10.1. Чому 1.6

| Аргумент | Пояснення |
|----------|-----------|
| Дихання між рядками | 1.6 — класична книжкова норма для засічкового шрифту в екрані. Менше 1.5 — рядки злипаються, більше 1.8 — текст розповзається |
| Для Georgia | Georgia має високі прописні та довгі виноски. 1.6 компенсує це візуально |
| Не для заголовків | Заголовки матимуть власний `line-height` (1.2–1.3) у лейаутах. `--leading` — для тексту, не для всього |

### 5.10.2. Чому 68ch

| Аргумент | Пояснення |
|----------|-----------|
| Оптимум читання | 60–75 символів на рядок — діапазон, за яким око не втомлюється повертатися. 68 — ближче до верхньої межі, бо Georgia вузький |
| `ch`, не `px`/`rem` | `ch` — ширина символу «0» поточного шрифту. Якщо шрифт зміниться — ширина адаптується. `px` — ні |
| Не центральна колонка | `--measure` обмежує текстовий блок, а не всю сторінку. Шапка, підвал, таблиці — повна ширина |

### 5.10.3. Де застосовується

| Елемент | `--leading` | `--measure` |
|---------|-------------|-------------|
| Тіло поста, есею | 1.6 | 68ch |
| Лід (перший абзац) | 1.6 | 68ch |
| Заголовки h1–h3 | 1.2–1.3 (лейаут) | 68ch |
| Мітки, дати, UI | 1.4 (лейаут) | не обмежується |
| Таблиці, код | 1.5 (лейаут) | повна ширина |

`--leading` та `--measure` — токени для текстового контенту. Лейаути
можуть перевизначати їх для не-текстових елементів, але текст завжди
повертається до цих значень.

### 5.10.4. Верифікація

| Перевірка | Де |
|-----------|-----|
| `--leading: 1.6` у `core.css` | токен |
| `--measure: 68ch` у `core.css` | токен |
| `ch`, не `px` | `--measure` використовує `ch`-одиницю |
| Застосування до `body`/`article` | лейаути (крок 114+) |

**Ритм — не декор.** Рядки, що злипаються, і занадто довгі рядки — дві
найчастіші причини, чому читач кидає довгий текст. Ці два токени —
мінімум, без якого архів не читається.

### 5.11. Буквиця

**Статус: ЗАТВЕРДЖЕНО** (крок 92, 2026-10-18).

Буквиця — перша літера першого абзацу, збільшена та опущена на кілька
рядків. Класичний засіб книжкової типографіки.

Реалізація: `src/styles/core.css`, клас `.dropcap`.

### 5.11.1. Де застосовується

| Розділ | Буквиця | Чому |
|--------|---------|------|
| `/blog/` (есеї, девлоги) | так | Довгий текст, книжкова читабельність |
| `/practice/` (кейси) | так | Довгий текст |
| `/poetry/` | ні | Ламає версифікацію. Вірш — не абзац |
| `/cemetery/` | ні | Занадто короткий. Буквиця без тексту — декор |
| `/now/`, `/manifest/` | ні | Службові сторінки, не література |
| Списки, таблиці | ні | Не абзаци |

**Клас ставить шаблон, не скрипт.** Шаблон поста (крок 114) додає
`class="dropcap"` до `<article>`. Автоматичного визначення «довгий текст»
не буде: поріг у словах — це магія, а не правило.

### 5.11.2. Параметри

| Властивість | Значення | Чому |
|-------------|----------|------|
| Шрифт | `var(--font-text)` | Той самий, що й текст. Не акцентний моно |
| Розмір | 3.4em | Класична буквиця на 3 рядки |
| `line-height` | 0.8 | Щоб літера не розтягувала перший рядок |
| Вага | 400 | Не жирна. Жирна буквиця — це 2007 рік |
| Колір | `var(--ink)` | Не `accent`. Буквиця — типографіка, не акцент |

### 5.11.3. Чому CSS, не картинка

| Аргумент | Пояснення |
|----------|-----------|
| 0 байт додатково | `::first-letter` — нативний псевдоелемент |
| Спадкує тему | `var(--ink)` підміняється при `prefers-color-scheme` без дублювання |
| Спадкує мову | Той самий CSS для uk та en. Літера — з тексту |
| Масштабується | Зум 200% — буквиця росте разом з текстом |

### 5.11.4. Обмеження

| Обмеження | Чому |
|-----------|------|
| Перший абзац, не перший символ документа | `::first-letter` застосовується до блоку з класом. Не до `<body>` |
| Не для тексту, що починається з лапок/цифри | Буквиця з лапки — виглядає зламано. Шаблон має перевіряти |
| `float: left` | Не `position: absolute`. Абсолют вириває літеру з потоку і ламає reflow |

### 5.11.5. Верифікація

| Перевірка | Де |
|-----------|-----|
| Клас `.dropcap` у `core.css` | реалізація |
| `::first-letter`, не картинка | CSS |
| `float: left`, не absolute | CSS |
| Жодного JS | `check.mjs` розділ 7а |
| Застосування: шаблон поста | крок 114 |

**Буквиця — не обов'язкова.** Якщо текст починається з цифри, лапки або
списку — шаблон не ставить клас. Примусова буквиця гірша за її відсутність.

## 6. РИТМ І ПРОСТІР (RHYTHM & SPACE)

**Статус: ЗАТВЕРДЖЕНО** (крок 93, 2026-10-18).

**Правило:** Порожній простір — не менше 20% будь-якого екрана. Це
повноправний елемент дизайну, а не «порожнеча, яку треба заповнити»
(`AGENTS.md` §4).

### 6.1. Що рахується порожнечею

| Рахується | Не рахується |
|-----------|--------------|
| Фон сторінки між елементами | Текст, зображення, іконки |
| Відступи між абзацами | Межі, лінійки |
| Поля навколо текстового блоку | Фон `surface` (блок коду, цитата) |
| Простір у шапці та підвалі | Табличні клітинки з контентом |
| Порожні лінки між секціями | `background-color` будь-якого елемента |

**Простір рахується від `--bg`.** Якщо піксель показує колір фону сторінки
і не містить контенту — це whitespace.

### 6.2. Чому 20%

| Аргумент | Пояснення |
|----------|-----------|
| Мінімум для дихання | Менше 20% — текст злипається в стіну. Читач бачить стіну, не документ |
| Не 50% | Занадто багато простору — сторінка виглядає порожньою та незавершеною. Архів має бути наповненим, але не тиснути |
| Машини | На 1366×768 (цільовий екран) 20% — це достатньо повітря, щоб текст не втомлював |

### 6.3. Як досягається

| Засіб | Значення | Крок |
|-------|----------|------|
| `--leading: 1.6` | Рядки дихають вертикально | 91 |
| `--measure: 68ch` | Рядки не розтягуються горизонтально | 91 |
| Поля текстового блоку | Визначаються лейаутами | 100+ |
| Відступи між секціями | Визначаються лейаутами | 100+ |

**Whitespace — не властивість окремого елемента.** Це властивість композиції.
Його неможливо «додати» до одного блоку — він з'являється від правильних
відстаней між блоками.

### 6.4. Верифікація

| Перевірка | Метод |
|-----------|-------|
| ≥ 20% на сторінці | Ручна: відкрити сторінку, оцінити частку фону |
| Ритм вертикальний | `--leading: 1.6` у `core.css` |
| Ритм горизонтальний | `--measure: 68ch` у `core.css` |

**Автоматизація неможлива без рендерингу.** Розрахунок частки фону потребує
відображення сторінки в пікселі — це робота браузера, не скрипта. Тому
whitespace перевіряється оком перед публікацією, як і решта візуальних
рішень (§2.7).

**Простір не заповнюється.** Якщо сторінка здається порожньою — це не
привід додати елемент. Це привід перечитати §1.2: «Whitespace ≥ 20% —
повноправний елемент, не порожнеча, яку треба заповнити».

### 6.5. Шкала відступів і меж

**Статус: ЗАТВЕРДЖЕНО** (аудит відступів, 2026-10-26).

**Правило:** будь-який рем-відступ кратний 0.25rem. Сітка:
0.25 · 0.5 · 0.75 · 1 · 1.25 · 1.5 · 1.75 · 2 · 2.5.

| Клас | Кроки | Де |
|------|-------|-----|
| Мікрогеп: мітки, рядки таблиць | 0.5 | паспорт, списки |
| Геп реєстрових рядків | 0.75 | тези, епітафії |
| Відступ усередині блоку | 1 — 1.25 | мітка → заголовок, теза → лід |
| Поля секцій | padding-top 1.75, margin-bottom 2.5 | головна |
| Плавна ритміка | лише `clamp(1.5rem, 4vw, 2.5rem)` | герой |

**Поза сіткою — лише em.** Відступи, прив'язані до кегля чи гліфа:
`1em` міжабзацних, `1.5em/0.5em` навколо заголовків (core.css),
мікрокорекції буквиці, лічильника, трекінгу. Em масштабується з текстом,
рем — із сіткою. Два класи не змішуються.

**Межі.** Єдиний роздільник — `1px solid var(--rule)`. Акцентна межа
лише станова: `2px solid var(--accent)` (заклик-лист, контент-попередження),
`1px solid var(--accent)` (skip-link у фокусі). Фокус — `outline: 2px solid
var(--accent)`, `outline-offset: 2px` (§9.5). Заокруглень немає (§2.3).

**Верифікація:**

| Перевірка | Як |
|-----------|----|
| Кратність 0.25 | автоматично: `check.mjs`, розділ 2 |
| Межі — лише дві змінні | `grep -rn "border" src/styles/` → `var(--rule)` / `var(--accent)` |
| Без заокруглень | `grep -rn "border-radius" src/styles/` → 0 |

## 7. СИГНАТУРИ (SIGNATURES)

**Статус: частково** (крок 94: лінійка. Кроки 95–97: глітч, курсор, перелік).

Три елементи. Не більше. Кожен — один момент несподіванки на сторінку
(§1.2, принцип 3). Це вичерпний перелік: будь-який четвертий елемент —
ознака того, що глітч перетворюється на стиль.

### 7.1. Лінійка запису

**Статус: ЗАТВЕРДЖЕНО** (крок 94, 2026-10-18).

Мітка з номером запису. Виводиться з поля `entry` front matter.

```html
<p class="entry-line">ЗАПИС №42</p>
```

| Параметр | Значення | Чому |
|----------|----------|------|
| Шрифт | `var(--font-mono)` | Моноширинний — сигнатурний засіб (§5.8.3) |
| Розмір | `--text-sm` | 12.8px. Мітка, не заголовок |
| Колір | `var(--ink-dim)` | Другорядний. Не `accent` — це не лінк |
| Регістр | ВЕРХНІЙ | Моноширинний у верхньому регістрі читається як системна мітка |

### 7.1.1. Правило незмінності

`entry` — незмінний номер з моменту першої публікації (`content-model.md`
§3.1). Він не змінюється при:

| Операція | `entry` |
|----------|---------|
| Перейменування slug | не змінюється |
| Перенесення між розділами | не змінюється |
| Оновленні тексту | не змінюється |
| Перекладі на en | той самий номер |
| Видаленні запису | номер не перевикористовується |

**Номер — це адреса.** Він не залежить від назви, розділу чи дати. Це
єдиний ідентифікатор, який переживе будь-яку реорганізацію сайту.

### 7.1.2. Де показується

| Сторінка | Лінійка | Приклад |
|----------|---------|---------|
| `/blog/[slug]/` | так | `ЗАПИС №42` |
| `/practice/[slug]/` | так | `ЗАПИС №57` |
| `/poetry/[slug]/` | так | `ЗАПИС №3` |
| `/cemetery/[slug]/` | так | `ЗАПИС №18` |
| Списки, індекси | ні | Зайве на кожному рядку |
| Службові сторінки | ні | Немає `entry` |

### 7.1.3. Чому моноширинний

Моноширинний стек — сигнатурний засіб (§5.8.3). Лінійка запису — його
перше застосування. Це не декор: моноширинний робить номер читабельним
як дані, а не як текст. Різниця між «ЗАПИС №42» моноширинним та
 Georgia очевидна — перше читається як системний вивід, друге як речення.

### 7.1.4. Верифікація

| Перевірка | Де |
|-----------|-----|
| `entry` незмінний | `validate-content.mjs` (дублікати) |
| Клас `.entry-line` у `core.css` | реалізація |
| Моноширинний шрифт | `var(--font-mono)` |
| ВЕРХНІЙ регістр | `text-transform: uppercase` |
| Без JS | генерується шаблоном Eleventy |

### 7.2. Мікрогліч на h1

**Статус: ЗАТВЕРДЖЕНО** (крок 95, 2026-10-18).

Короткий зсув заголовка при завантаженні сторінки. 150 мс, один раз.

| Параметр | Значення | Чому |
|----------|----------|------|
| Тривалість | 150 мс | Достатньо, щоб помітити. Занадто швидко — не видно, занадто довго — дратує |
| Властивості | `transform`, `opacity` | 2D-трансформації. 3D заборонено (§2.5), але 2D дозволено як виняток |
| Запуск | Один раз, при завантаженні | Не на hover. Не в циклі. Це не заставка |
| Зменшення руху | `prefers-reduced-motion: reduce` → `animation: none` | Обов'язково. vestibular triggers — реальна причина |

### 7.2.1. Реалізація

CSS-анімація на `h1`. Без JS. Без зовнішніх бібліотек.

```css
@keyframes glitch-shift {
  0%   { transform: translateX(-3px); opacity: 0; }
  40%  { transform: translateX(2px);  opacity: 1; }
  70%  { transform: translateX(-1px); }
  100% { transform: translateX(0); }
}

h1 {
  animation: glitch-shift 150ms ease-out;
}

@media (prefers-reduced-motion: reduce) {
  h1 { animation: none; }
}
```

Реалізація: `src/styles/core.css`.

### 7.2.2. Чому 150 мс

| Аргумент | Пояснення |
|----------|-----------|
| Межа сприйняття | Людське око помічає рух від 50 мс. 150 мс — верхня межа «одного кивка» |
| Не 300+ | Довше за 300 мс — заголовок «приїжджає». Це не глітч, це entrance-анімація з кожного шаблону |
| Одного разу | Циклічний глітч — це фонова анімована ілюстрація. Заборонено (§2.6) |

### 7.2.3. Чому лише transform та opacity

| Властивість | Ламає | Дозволена |
|-------------|-------|-----------|
| `transform: translateX()` | Ні. GPU-прискорення, без reflow | ✅ |
| `opacity` | Ні. Композитинг | ✅ |
| `width`, `height`, `top`, `left` | Так. reflow кожен кадр | ❌ |
| `filter` | Так. Розрахунок на CPU | ❌ |
| `box-shadow` | Так. Заборонено взагалі (§2.2) | ❌ |

**Це не 3D.** `translateX()` — двовимірна трансформація. `perspective` та
`rotate3d` не використовуються (§2.5).

### 7.2.4. Де застосовується

| Елемент | Застосовується | Чому |
|---------|----------------|------|
| `h1` кожної сторінки | так | Сигнатура глітчу |
| `h2`, `h3` | ні | Заголовки нижчого рівня — не сигнатурні |
| Лінки, кнопки | ні | Інтерактив — не глітч |
| Фон, зображення | ні | Анімовані фони заборонені (§2.6) |

### 7.2.5. Верифікація

| Перевірка | Де |
|-----------|-----|
| `@keyframes glitch-shift` у `core.css` | реалізація |
| `animation: none` при `prefers-reduced-motion` | реалізація |
| Тривалість 150 мс | `core.css` |
| 0 байт JS | `check.mjs` розділ 7а |
| `transform`/`opacity` лише | `core.css` (ручна) |

### 7.3. Курсор ▍

**Статус: ЗАТВЕРДЖЕНО** (крок 96, 2026-10-18).

Миготливий курсор текстового редактора. Символ `▍` (U+258D, LEFT FIVE
EIGHTHS BLOCK). Стоїть у кінці маніфесту.

| Параметр | Значення | Чому |
|----------|----------|------|
| Символ | `▍` (U+258D) | Уже в сабсеті IBM Plex Mono |
| Шрифт | `var(--font-mono)` | Моноширинний — сигнатурний засіб (§5.8.3) |
| Колір | `var(--ink)` | Не `accent`. Це не лінк |
| Миготіння | 1 клік/сек | Класична швидкість текстового редактора |
| Зменшення руху | `prefers-reduced-motion` → `display: none` | `TECH_STANDARDS.md` §5: «Гліч і курсор ▍ вимикаються» |

### 7.3.1. Реалізація

Псевдоелемент `::after`. Без JS. Без зовнішніх бібліотек.

```css
.cursor-blink::after {
  content: "▍";
  font-family: var(--font-mono);
  color: var(--ink);
  animation: blink 1s step-end infinite;
}

@keyframes blink {
  0%, 100% { opacity: 1; }
  50%      { opacity: 0; }
}

@media (prefers-reduced-motion: reduce) {
  .cursor-blink::after { display: none; }
}
```

Реалізація: `src/styles/core.css`.

### 7.3.2. Чому step-end

`step-end` — не `ease`. Миготливий курсор не «тільмає» між 1 та 0.
Він стрибає: видимий 500 мс, невидимий 500 мс. `ease` дав би плавне
затемнення — це не курсор, це нагадування.

### 7.3.3. Чому після маніфесту

| Аргумент | Пояснення |
|----------|-----------|
| Архів у процесі | Маніфест — чи не єдиний документ сайту, який має право змінюватись. Курсор каже: «текст не закритий» |
| Не після кожного тексту | Курсор після будь-якого поста — це шаблон. Після маніфесту — це рішення |
| Маніфест — перший | `/manifest/` у шапці (sitemap.md, рядок 18). Курсор помітний з першого відвідування |

### 7.3.4. Де застосовується

| Сторінка | Курсор | Чому |
|----------|--------|------|
| `/manifest/` | так | Маніфест у процесі |
| Решта сторінок | ні | Архів закритий. Курсор після кожного тексту — шаблон |

**Клас `.cursor-blink` ставить шаблон сторінки** (`page.njk`, крок 115+),
не скрипт. Шаблон знає, що це маніфест.

### 7.4. Вичерпний перелік

**Статус: ЗАТВЕРДЖЕНО** (крок 97, 2026-10-18).

**Це все.** Три сигнатурі. Не чотири. Не «поки що три». Не «три плюс
майбутні». Рівно три.

| # | Сигнатура | Крок | Застосування | Активна |
|---|-----------|------|--------------|---------|
| 1 | Лінійка запису (`entry`) | 94 | Кожен запис | завжди |
| 2 | Мікрогліч на `h1` | 95 | Кожна сторінка | завжди |
| 3 | Курсор ▍ | 96 | Лише `/manifest/` | завжди |

### 7.4.1. Чому саме три

| Аргумент | Пояснення |
|----------|-----------|
| Помітність | 3 сигнатурі на сторінку — максимум, який читач сприймає як «свідома деталь». 4+ — це вже стиль, а не акцент |
| Вичерпність | Перелік, який можна перелічити пам'яттю — це правило. Перелік, який потребує документа — це каталог |
| Дисципліна | Якщо з'являється четверта сигнатура — одна з попередніх має померти. Не «додатись», а «замінитись» |

### 7.4.2. Що НЕ є сигнатурою

| Елемент | Чому не сигнатура |
|---------|-------------------|
| Ховер-ефекти на лінках | Стандартна взаємодія. Не глітч |
| Підкреслення лінок | Типографіка, не збій |
| Hover-стан карток | Не реалізовано. Якщо з'явиться — не сигнатура |
| Будь-яка анімація завантаження | Заборонена (§2.6). Виняток — лише мікрогліч на `h1` |
| Емодзі, іконки | Не глітч. Це контент або UI |

### 7.4.3. Правило четвертої сигнатури

**Четверта сигнатура заборонена.** Без обговорення. Без «але це інше».

Якщо виникне бажання додати четвертий елемент:

1. Спитай: яку з трьох наявних він замінює?
2. Якщо відповіді немає — це не сигнатура. Це оздоблення. Заборонено (§1.2).
3. Якщо відповідь є — видаляй попередню, додавай нову. Не додавай поверх.

**Цей перелік — частина ідентичності сайту.** ВУЗОЛ-0 впізнається за цими
трьома деталями. Четверта зробить його «сайтом з глітчем», а не «архівом,
у якого є глітч».

### 7.4.4. Верифікація

| Перевірка | Де |
|-----------|-----|
| 3 сигнатурі у `core.css` | `.entry-line`, `glitch-shift`, `.cursor-blink` |
| Жодного четвертого `@keyframes` | `core.css` |
| Жодного четвертого анімованого класу | `core.css` |
| `check.mjs` розділ 7а | 0 байт JS |

**Автоматизації «трьох сигнатур» немає.** Це правило, не лічильник.
Але `core.css` — єдиний файл з анімаціями. Якщо в ньому з'явиться
четвертий `@keyframes` — це порушення цього розділу.

### 8.1. Перемикач мови

### 8.1.1. Мовна схема

| Мова | URL | Статус |
|------|-----|--------|
| Українська | `/` (корінь) | Коренева. Завжди перша |
| Англійська | `/en/` | Паралельна гілка |

**Без редиректів.** `/` — це українська. Точка. `x-default` у hreflang —
`https://koztechie.fyi/` (українська, `DECISIONS.md` §19.0).

«Not translated. Read the original in Ukrainian →» (`DECISIONS.md` §19.4).

### 8.1.2. Реалізація

HTML-розмітка (шаблон шапки, крок 108+):

```html
<nav class="lang-switch" aria-label="Мова">
  <span class="current" hreflang="uk">УКР</span>
  <span aria-hidden="true">/</span>
  <a href="/en/manifest/" hreflang="en">ENG</a>
</nav>
```

CSS: `src/styles/core.css`.

### 8.1.3. hreflang — окремо від UI

Мітка «УКР / ENG» — це видимий інтерфейс. `hreflang` — це метадані для
пошукових роботів. Вони не залежать одна від одної.

| Де | Що |
|----|-----|
| `<head>` | `<link rel="alternate" hreflang="uk" href="...">`, `hreflang="en"`, `hreflang="x-default"` |
| Шапка (видима) | `УКР / ENG` |

`hreflang` генерується шаблоном (крок 112). Мітка — теж шаблоном. Обидва
залишаються статичними HTML-атрибутами.

### 8.1.4. Верифікація

| Перевірка | Де |
|-----------|-----|
| Клас `.lang-switch` у `core.css` | реалізація |
| Поточна мова — `<span>`, не `<a>` | HTML-розмітка (крок 108) |
| `hreflang` у `<head>` | шаблон (крок 112) |
| Без JS | навігація — звичайні лінки |
| `aria-label` на `<nav>` | доступність (§5 AGENTS) |

### 8.2. Тема: без перемикача

**Статус: ЗАТВЕРДЖЕНО** (крок 99, 2026-10-18).

Тема визначається операційною системою читача. Не сайтом.

```css
@media (prefers-color-scheme: dark) { /* БУНКЕР */ }
```

**Немає перемикача теми.** Немає іконки сонця/місяця. Немає перемикача
в шапці чи підвалі. Немає JS, який запам'ятовує вибір.

### 8.2.1. Чому без перемикача

| Аргумент | Пояснення |
|----------|-----------|
| ОС вже має перемикач | Кожна ОС має темний/світлий режим. Дублювати його на сайті — додавати другий перемикач на одну дію |
| 0 JS | Перемикач теми потребує збереження вибору. `localStorage` заборонено (`DECISIONS.md` §16). Без збереження — перемикач марний |
| Не наша роль | Сайт — архів, не налаштування. Читач налаштовує ОС, не сайт |
| `theme.js` — 3 КБ | Заради того, що ОС робить безкоштовно (`TECH_STANDARDS.md` §5) |

### 8.2.2. Чому без збереження

| Аргумент | Пояснення |
|----------|-----------|
| `localStorage` заборонено | `DECISIONS.md` §16: «нуль збереження». Жодних куків, жодного збереження стану |
| Нуль приватності | Збереження вибору теми — це мінімальний, але реальний слід. ВУЗОЛ-0 не залишає слідів |
| ОС — джерело істини | Якщо читач змінив тему в ОС — сайт підхопить. Без перезавантаження. Без збереження |

### 8.2.3. Реалізація

`src/styles/themes.css` (крок 85):

```css
:root { color-scheme: light; /* ПАПІР */ }
@media (prefers-color-scheme: dark) {
  :root { color-scheme: dark; /* БУНКЕР */ }
}
```

`color-scheme: light/dark` — додатковий сигнал браузеру для нативних
елементів (скролбари, форми). Це не CSS-перемикач, це метадані.

### 8.2.4. Верифікація

| Перевірка | Де |
|-----------|-----|
| `@media (prefers-color-scheme: dark)` у `themes.css` | реалізація |
| `color-scheme: light` та `dark` | `themes.css` |
| Жодного `.theme-toggle` | `core.css`, `themes.css` |
| Жодного `localStorage` | `check.mjs` (JS: 0 байт) |
| Жодного `theme.js` | `check.mjs` розділ 7а |

**Немає чого документувати більше.** Це рішення полягає у відсутності
коду. Найкращий перемикач теми — той, якого немає.

| Підвал | обов'язково | Як і на кожній сторінці |
| «Повернутись на головну» | заборонено | Навігація вже містить посилання на головну |

### 9.8.3. Чому без «повернутись на головну»

| Аргумент | Пояснення |
|----------|-----------|
| Дублювання | Лінк «Головна» вже є в шапці (§9.6.2). Другий — зайвий |
| Клікбейт | «Повернутись» — заклик. Архів не закликає, він фіксує |
| Доступність | Клавіатурний читач проходить шапку першою. Він уже «на головній» |

### 9.8.4. HTTP-код

`404`. Не `200`. Не `301`. Сторінка повертає `404` через Eleventy
(`permalink: /404.html`).

**Не включається до sitemap** (`DECISIONS.md` §17.1) та `hreflang`.
Мова не має значення: `/404/` однакова для uk та en.
